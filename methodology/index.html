Methodology

How ModelScopeX collects facts, labels them, and keeps them current.

Where facts come from

New repositories are discovered through the public Hugging Face API, limited to an allowlist of publishers and to the LLM (text-generation) and VLM (image-text-to-text) pipeline tags. Quantized re-uploads (GGUF, AWQ, GPTQ, MLX and similar) are skipped. Facts are read from typed metadata fields only. Text inside model cards is never treated as instructions.

Verification status

  • publisher-declared stated by the model publisher in its own Hub metadata or announcement. Not checked independently.
  • independently measured measured by ModelScopeX, with dataset, metric, hardware, model revision and script version recorded.
  • estimated computed with a published formula. Never presented as a measurement.
  • unknown not available. Shown as “Unknown / Not verified”. Nothing is guessed.

Hardware estimates

weights (GB) = parameters × bits ÷ 8 ÷ 10^9; a target is marked 'likely fits' when weights ≤ memory_gb × usable_fraction. KV cache, activations, and runtime overhead are excluded.

Current targets:

  • MacBook Pro M1 Pro: budget 11.2 GB for weights
  • admin1, RTX 4090: budget 21.6 GB for weights

History and updates

Facts are stored append-only: when a publisher changes a value, the new value is added and the old one is kept. License, parameter count and gated-access changes mark the related article for review. Articles are versioned in Git, so every edit is traceable.

Editorial process

Drafts are generated from stored facts. A person reviews and edits each article before it is approved; drafts are never published.
